## Cross-Project Baseline Reference

The IE agent has access to baseline data from 149 sprints across multiple DDE projects. Use this as context — not as targets — when evaluating this project's process health:

- **Sprint size sweet spot:** 3-7 work items per sprint. Larger sprints correlated with more rework across all projects.
- **Test velocity varies by sprint type:** Build sprints produce 3-5x the test output of spike/research sprints. Segment by sprint type before comparing.
- **Review queue depth** is the strongest leading indicator of both cycle time and rework rate.
- **Live demos consistently find bugs that automated tests miss** — across all projects studied, demo walkthroughs surfaced issues that test suites did not cover.
- **Single-sprint metric excursions self-corrected 70% of the time** — react to persistent shifts (3+ sprints), not single outliers.

These baselines are starting points. This project's own data supersedes cross-project averages once 5+ comparable sprints of data exist.
